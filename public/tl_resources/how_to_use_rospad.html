Learn ROS2 in the Browser

ROSpad is a browser-based ROS2 IDE with a live 3D simulator. No installation required — write Python nodes, launch packages, and see your robot move, all from a browser tab.

🐍 Python nodes 🤖 Live 3D sim 📦 ROS2 packages ⚡ Launch files
Getting Started
🔐
Logging In Beginner ›

ROSpad uses GitHub for authentication. Your workspace files are stored in a private GitHub repository in your own account — no shared server, no passwords to manage.

  1. Create a GitHub account at github.com if you don't have one.
  2. Create a repository named exactly rospad-workspace in your GitHub account (public or private). There is a direct link on the ROSpad login page.
  3. Open ROSpad at niravatgit.github.io/ROSPad/ and click Login with GitHub.
  4. Authorize the ROSpad app — GitHub will ask which repositories to allow. Select rospad-workspace.
  5. You land on the IDE. System packages (the ROS2 Python shim and core utilities) are seeded automatically — a spinner appears in the top bar while this runs. Demo packages are not installed automatically; add them one at a time with the ⊕ Add Package button in the file explorer sidebar.
ℹ️ Steps 1 and 2 are one-time setup. After that, clicking Login with GitHub takes you straight to the IDE in a few seconds.
ℹ️ Your workspace is your private GitHub repo — no other student can see your files. You can also view and edit your files directly on GitHub at github.com/<your-username>/rospad-workspace.

!Button reference›

Top toolbar

  • ▶ Run — enabled only when a .py file (non-launch) is open and no node is running.
  • ⚡ Launch — enabled only when a .launch.py file is open and no node is running.
  • ■ Stop — enabled only when a node is running. Stops all nodes across all terminal sessions.
  • ↺ Reset — always enabled. Stops all running nodes and clears the 3D simulator. Does not touch workspace files.

File explorer sidebar

  • + New File — always enabled. Creates a blank file at a path you specify.
  • ⊕ Add Package — always enabled. Opens the package picker to install one demo package.
  • ⊖ Clear Workspace — always enabled. Asks for confirmation, then removes all packages from src/ with no re-seeding.
  • ↺ Refresh — always enabled. Re-reads the file tree from GitHub. Does not stop nodes or change files.
  • ⊘ Reset — always enabled. Asks for confirmation, then wipes src/ and re-seeds the full demo collection. Also stops nodes and clears the sim.

The file explorer sidebar has five buttons in the top-right corner. Each one manages the packages in your workspace differently — here is what each one does and when to use it.

💡Teaching workflow — build the workspace together›

ROSpad is designed for progressive classroom discovery. The recommended flow:

  1. Login — robot description packages (diffbot_description, ur5_description, etc.) are seeded automatically. The workspace is otherwise nearly empty.
  2. ⊕ Add Package — install demo packages one at a time as the session progresses. Students see each package appear live in their explorer and can explore it before running anything.
  3. ⊖ Clear Workspace — at the start of a new topic or exercise, wipe the workspace and begin building again from scratch.
  4. ⊘ Reset — if you need all demos at once (exam prep, self-study) or want to recover a clean state, Reset seeds the complete collection in one click.
💡 The file tree refreshes automatically after every add, clear, and reset — you don't need to click ↺ manually.
💡Using the ⊕ package picker›

Click ⊕ to open the picker overlay. A list of all available demo packages appears, each with a short description.

  • Packages already in your workspace are marked Installed.
  • Click any package name to select it and see its description.
  • If it is already installed, a yellow warning reads "These files will be overwritten." Click Overwrite Files to confirm, or choose a different package.
  • Click Install Package to seed it. A progress bar shows each file as it is written.
  • Click ✕ Close or press Escape to dismiss without installing anything.

Tutorial 1 — Talker / Listener
📢
Hello ROS2: Publish & Subscribe Beginner ›

The classic ROS2 demo: one node publishes messages, another subscribes. You'll create a Python package with two nodes and run them in separate terminal sessions.

1Create the package›

In the terminal, type:

$ros2 pkg create my_talker

This creates the directory src/my_talker/ with package.xml, setup.py, and a default node stub. You will see it appear in the file explorer.

💡You can also click + File in the toolbar and type the path manually, but using ros2 pkg create sets up all required files at once.
2Write the talker node›

In the file explorer, open src/my_talker/my_talker/my_node.py. Replace its contents with:

Python — talker.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class Talker(Node):
    def __init__(self):
        super().__init__('talker')
        self.pub   = self.create_publisher(String, '/chatter', 10)
        self.timer = self.create_timer(1.0, self.publish_msg)
        self.count = 0
        self.get_logger().info('Talker started!')

    def publish_msg(self):
        msg = String()
        msg.data = f'Hello ROS2! count={self.count}'
        self.pub.publish(msg)
        self.get_logger().info(f'Publishing: {msg.data}')
        self.count += 1


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(Talker())
    rclpy.shutdown()

Click ▶ Run. You should see "Talker started!" in the terminal, followed by publish messages every second.

3Write and run the listener›

Click + next to the terminal tabs to open a second terminal session. Then click + File and create src/my_talker/my_talker/listener.py:

Python — listener.py
import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class Listener(Node):
    def __init__(self):
        super().__init__('listener')
        self.sub = self.create_subscription(
            String, '/chatter', self.on_msg, 10)
        self.get_logger().info('Listener ready — waiting for messages…')

    def on_msg(self, msg):
        self.get_logger().info(f'Heard: {msg.data}')


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(Listener())
    rclpy.shutdown()

Open listener.py in the editor, then click ▶ Run. You will see the messages arriving from the talker.

💡To stop, click ■ Stop. This stops all running nodes.
4Inspect the topic in the terminal›

While the talker is running, try these in the terminal:

$ros2 topic list
$ros2 topic echo /chatter
$ros2 topic hz /chatter
ℹ️You can also open the Topics tab in the right panel to see a live dashboard of all active topics.
5Create a launch file (optional)›

Add both nodes to a launch file so they start together. Create src/my_talker/launch/demo.launch.py:

Python — demo.launch.py
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(package='my_talker', executable='my_node', name='talker'),
        Node(package='my_talker', executable='listener', name='listener'),
    ])

Also add the listener entry point to setup.py. Open it and add 'listener = my_talker.listener:main' to console_scripts. Then open demo.launch.py and click ⚡ Launch.

Tutorial 2 — Turtlesim
🐢
Draw with a Turtle Beginner ›

Write a node that moves a turtle through a 2D canvas by publishing its pose. The sim automatically switches to turtle view when messages arrive on /turtle1/pose.

ℹ️The turtle canvas is an 11×11 unit grid (0–11 on both axes). The turtle starts at (5.5, 5.5). Publish a sequence of poses to trace a path.
1Create the package›
$ros2 pkg create turtle_demo
2Write the circle drawer›

Open src/turtle_demo/turtle_demo/my_node.py and replace with:

Python — turtle_circle.py
import math
import rclpy
from rclpy.node import Node


class TurtleCircle(Node):
    def __init__(self):
        super().__init__('turtle_circle')
        # Use raw rosBus to publish turtlesim pose
        import js
        self.bus = js.window.rosBus
        self.t   = 0.0
        self.timer = self.create_timer(0.05, self.step)
        self.get_logger().info('Turtle circle started!')

    def step(self):
        self.t += 0.05
        x     = 5.5 + 3.0 * math.cos(self.t)
        y     = 5.5 + 3.0 * math.sin(self.t)
        theta = self.t + math.pi / 2
        self.bus.publish(
            '/turtle1/pose', 'turtlesim/Pose',
            {'x': x, 'y': y, 'theta': theta,
             'linear_velocity': 1.0, 'angular_velocity': 1.0}
        )


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(TurtleCircle())
    rclpy.shutdown()

Click ▶ Run. The sim switches to the turtle canvas and draws a circle. Click ■ Stop when done.

3Try a spiral or square›

Change the step() method to draw a square:

Python — square path
    def step(self):
        self.t += 0.05
        side   = 4.0           # square side length
        period = self.t % (4 * side / 1.0)
        seg    = int(period / side)  # which side 0–3
        s      = period % side         # distance along side
        corners = [(2,2), (9,2), (9,9), (2,9)]
        cx0, cy0 = corners[seg]
        cx1, cy1 = corners[(seg+1) % 4]
        t = s / side
        x = cx0 + t * (cx1 - cx0)
        y = cy0 + t * (cy1 - cy0)
        self.bus.publish('/turtle1/pose', 'turtlesim/Pose',
                         {'x': x, 'y': y, 'theta': 0.0})

3Create a controller package›
$ros2 pkg create my_diffbot_ctrl

Open src/my_diffbot_ctrl/my_diffbot_ctrl/my_node.py and replace with a simple forward-move controller:

Python — simple_drive.py
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist


class DriveForward(Node):
    def __init__(self):
        super().__init__('drive_forward')
        self.pub   = self.create_publisher(Twist, '/cmd_vel', 10)
        self.timer = self.create_timer(0.1, self.drive)
        self.get_logger().info('Driving forward at 0.3 m/s')

    def drive(self):
        msg = Twist()
        msg.linear.x  = 0.3   # m/s forward
        msg.angular.z = 0.0   # no turning
        self.pub.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(DriveForward())
    rclpy.shutdown()

Keep the launch file running. In a new terminal session, open the controller file and click ▶ Run. The robot moves forward. Click ■ Stop to halt.

4Read odometry›

import rclpy
from rclpy.node import Node
from nav_msgs.msg import Odometry


class OdomReader(Node):

    def cb(self, msg):
        x = msg.pose.pose.position.x
        y = msg.pose.pose.position.y
        self.get_logger().info(f'Position: x={x:.3f}  y={y:.3f}')


def main(args=None):

Python — joint_publisher.py
import math
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState

JOINTS = [
    'shoulder_pan_joint', 'shoulder_lift_joint', 'elbow_joint',
    'wrist_1_joint',      'wrist_2_joint',       'wrist_3_joint',
]

# Edit these angles (radians) to move the arm
POSITIONS = [0.0, -1.57, 0.0, -1.57, 0.0, 0.0]


class JointPublisher(Node):
    def __init__(self):
        super().__init__('joint_publisher')
        self.pub   = self.create_publisher(JointState, '/joint_states', 10)
        self.timer = self.create_timer(0.05, self.publish)
        self.get_logger().info('Publishing joint states at 20 Hz')

    def publish(self):
        msg = JointState()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.name     = JOINTS
        msg.position = list(POSITIONS)
        msg.velocity = [0.0] * 6
        msg.effort   = [0.0] * 6
        self.pub.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(JointPublisher())
    rclpy.shutdown()

Edit POSITIONS to set joint angles, then click ▶ Run.

💡Joint values are in radians. −1.57 ≈ −90°, 1.57 ≈ 90°. Positive elbow_joint bends the arm upward.
4Animate the arm with a sine wave›

Create src/my_ur5_ctrl/my_ur5_ctrl/sine_demo.py:

Python — sine_demo.py
import math, rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState

JOINTS = ['shoulder_pan_joint', 'shoulder_lift_joint',
          'elbow_joint', 'wrist_1_joint',
          'wrist_2_joint', 'wrist_3_joint']

AMP  = [0.8, 0.4, 0.6, 0.4, 0.5, 0.3]
FREQ = [0.3, 0.5, 0.4, 0.7, 0.6, 0.9]
OFF  = [0.0, -1.57, 0.0, -1.57, 0.0, 0.0]


class SineDemo(Node):
    def __init__(self):
        super().__init__('sine_demo')
        self.pub   = self.create_publisher(JointState, '/joint_states', 10)
        self.timer = self.create_timer(0.033, self.step)
        self.t = 0.0

    def step(self):
        self.t += 0.033
        pos = [OFF[i] + AMP[i] * math.sin(2*math.pi*FREQ[i]*self.t)
               for i in range(6)]
        msg = JointState()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.name = JOINTS; msg.position = pos
        msg.velocity = [0.0]*6; msg.effort = [0.0]*6
        self.pub.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(SineDemo())
    rclpy.shutdown()

Open sine_demo.py and click ▶ Run. The arm dances through smooth sine-wave motion across all 6 joints.

Tutorial 5 — ROS2 Services
🔁
AddTwoInts — the classic service tutorial Beginner ›

A service is a synchronous request-response call between two nodes — unlike topics (fire-and-forget), a service client waits for a reply. This tutorial uses the standard example_interfaces/srv/AddTwoInts service type, the same one in the official ROS2 docs.

1Seed the demo package›

The service_demo package is under src/demos/service_demo/ in your workspace. If it isn't there yet, click the ⊘ Reset button in the file tree sidebar to re-seed all demo packages.

Open src/demos/service_demo/ to explore the package before running anything.

2Start the service server›

Expand service_demo → launch and open service_demo.launch.py. Click ⚡ Launch.

The terminal prints:

[server] Service /add_two_ints is ready — waiting for requests
ℹ️The server keeps running in the background, waiting for calls. Leave it running and open the client in the next step.
3Run the client›

Open src/demos/service_demo/service_demo/add_two_ints_client.py. Click ▶ Run.

After 1.5 seconds the client calls the server and both terminals update:

[server]  Request: 3 + 4 = 7
[client]  Result: 3 + 4 = 7
💡Edit A and B at the top of the client file and click ▶ Run again to try different numbers.
4Write your own service call›

The service pattern in Python:

Python — service call pattern
import asyncio, rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts

class MyClient(Node):
    def __init__(self):
        super().__init__('my_client')
        self.cli   = self.create_client(AddTwoInts, '/add_two_ints')
        self._done = False
        self.create_timer(1.5, self._call_once)

    def _call_once(self):
        if self._done: return
        self._done = True
        asyncio.ensure_future(self._do_call())

    async def _do_call(self):
        req = AddTwoInts.Request()
        req.a = 10; req.b = 20
        resp = await self.cli.call_async(req)
        self.get_logger().info(f'Result: {resp.sum}')

def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(MyClient())
    rclpy.shutdown()

Key points: service calls are async — use asyncio.ensure_future() from a timer callback to schedule them, then await client.call_async(req) inside an async def.

Tips & Troubleshooting ›
?The sim panel is empty›

The sim starts empty. Launch a package (e.g. diffbot_bringup.launch.py or ur5_bringup.launch.py) to load a robot. The robot loads automatically when the launch file publishes /robot_description.

?▶ Run is greyed out›

Run is enabled only for .py files (not launch files, not URDF). Open a Python node file in the editor. Also check that no node is currently running (Stop first if needed).

?⚡ Launch is greyed out›

Launch is enabled only for .launch.py files. Open a launch file (from your workspace or from System Packages). Also stop any running nodes first.

?My node crashed / keeps restarting›

Click ■ Stop to terminate all nodes. Check the terminal for the error traceback. Python syntax errors and import errors are the most common causes.

?The arm/robot doesn't move after I run my node›

Make sure the launch file is still running (it must stay active to keep the robot in the sim). Check the terminal for errors. Verify your topic name matches exactly — ROS2 topic names are case-sensitive.

?I can't see a topic I just created›

Topics only appear when a node is publishing or subscribing. Run your node first, then check ros2 topic list in the terminal or look in the Topics panel.

?The file tree doesn't update after adding / removing packages›

The explorer normally refreshes automatically after every add, clear, and reset. If it still looks stale, click the ↺ Refresh button (sidebar, 4th button). It bypasses the browser cache and re-reads your GitHub repository directly.

?⊕ Add Package shows "Failed to load packages"›

Your browser loaded an old cached version of ROSpad's JavaScript. Press Ctrl + Shift + R (Windows/Linux) or ⌘ + Shift + R (Mac) to force a hard reload, then try again.

?All packages show "Installed" in the picker even for a new workspace›

Press Ctrl + Shift + R (or ⌘ + Shift + R on Mac) to clear stale browser cache. The picker re-checks each package path directly against your GitHub repository after a clean reload.

?The simulator still shows the robot after clicking Reset›

Use the ↺ Reset button in the top toolbar (not the ⊘ in the sidebar). The top toolbar Reset explicitly stops all nodes and clears the 3D simulator scene — robot meshes, obstacles, and physics bodies are all removed.
