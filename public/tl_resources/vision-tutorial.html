How URDF cameras work in ROSpad

ROSpad's simulator reads your robot's URDF and looks for Gazebo camera sensor declarations. When it finds one, it automatically:

A
Creates a Three.js PerspectiveCamera and attaches it to the declared link (e.g. camera_link on DiffBot, wrist_camera_link on UR5).
B
Renders the 3D scene from that camera's viewpoint 10 times per second into an offscreen WebGLRenderTarget.
C
Reads the pixel data and publishes it as sensor_msgs/Image on the topic declared in the URDF's <remapping> tag.
D
Any Python node can subscribe to that topic and receive live image frames as NumPy arrays.

The camera sensor is declared with Gazebo-compatible XML so the same URDF works in both ROSpad (browser) and real Gazebo (on a Linux machine):

XML — in any .urdf file
<!-- 1. Add a link for the camera body --> <link name="camera_link"> <visual><geometry><box size="0.03 0.06 0.04"/></geometry></visual> </link> <!-- 2. Attach it to the robot with a fixed joint --> <joint name="camera_joint" type="fixed"> <parent link="base_link"/> <child link="camera_link"/> <origin xyz="0.15 0 0.16" rpy="0 0 0"/> <!-- 15 cm forward, 16 cm up --> </joint> <!-- 3. Declare the sensor and its topic --> <gazebo reference="camera_link"> <sensor type="camera" name="front_camera"> <camera> <horizontal_fov>1.0472</horizontal_fov> <!-- 60° --> <image><width>320</width><height>240</height></image> </camera> <plugin name="rospad_camera" filename="libgazebo_ros_camera.so"> <ros><remapping>~/image_raw:=/camera/image_raw</remapping></ros> <frame_name>camera_link</frame_name> </plugin> </sensor> </gazebo>
📷

No extra node needed. The camera is run entirely by the simulator bridge. Just launching the URDF is enough to start publishing images.

New packages overview

diffbot_camera_description
DiffBot URDF with front-facing camera. Extends the base DiffBot with a camera_link mounted 15 cm forward and 16 cm up from the chassis centre. Publishes images on /camera/image_raw.
ur5_camera_description
UR5 URDF with wrist (eye-in-hand) camera. Adds wrist_camera_link at the tool0 position on wrist_3. Camera view changes with arm pose. Publishes on /wrist_camera/image_raw.
diffbot_vision
DiffBot vision node. Contains color_tracker — steers the DiffBot toward a coloured obstacle using the front camera.
ur5_vision
UR5 vision nodes. Contains wrist_detector (logs coloured object positions from UR5 wrist cam) and image_info (quick pipeline sanity check).

1
Launch the DiffBot with camera URDF.
Click the ⚡ launch icon on diffbot_camera_description, or run in terminal: 
$ ros2 launch diffbot_camera_description diffbot_camera.launch.py
[launch] Published /robot_description (4.2 kB)
[sim] DiffBot loaded — camera rig attached to camera_link
[sim] Publishing /camera/image_raw at 10 Hz
The DiffBot appears in the sim. A small camera body is visible on the front.
2
Verify the camera feed.
Open the Topics tab in the right panel. You should see /camera/image_raw at ~10 Hz. Click it — the inspector shows a live canvas preview of what the robot sees.
💡

The Viz panel also has a checkbox for /camera/image_raw. Enabling it overlays a small camera window in the corner of the 3D sim viewport.

3
Add a coloured target.
In the sim panel, click + Box (or Sphere) in the Obstacles area. Then select the obstacle and set its colour to a bright red (#ff2020) in the colour picker. Place it a few metres in front of the robot.
📐

The color_tracker node detects red pixels (R>150, G<80, B<80). Any bright red obstacle works. You can also edit the thresholds in the source file to track other colours.

4
Run the vision node. 
$ ros2 run diffbot_vision color_tracker
[INFO] [color_tracker]: ColorTracker started — waiting for /camera/image_raw
[INFO] [color_tracker]: Searching... (red pixels: 0)
[INFO] [color_tracker]: Target at cx=178px  offset=+0.11  area=3.2%  vx=0.27  wz=-0.09

The robot will spin while no red is visible, then lock on and steer toward the target.

5
Watch the perception-action loop in the Topics panel. You can see /camera/image_raw and /cmd_vel both active and updating. The robot adjusts its heading as the target moves in the image frame.

Open diffbot_vision/color_tracker.py in the editor to explore the numpy-based detection logic. The key section:

Python — diffbot/diffbot_vision/diffbot_vision/color_tracker.py
def _on_image(self, msg): # called for every camera frame w, h = msg.width, msg.height # image dimensions in pixels # Convert JsProxy Uint8Array → NumPy RGB array (h rows × w columns × 3 channels) arr = np.asarray(msg.data, dtype=np.uint8).reshape(h, w, 3) # Boolean mask: True where pixel is "red enough" (R high, G and B low) red_mask = (arr[:, :, 0] > 150) & (arr[:, :, 1] < 80) & (arr[:, :, 2] < 80) if np.sum(red_mask) < 50: # fewer than 50 red pixels — target not found twist.angular.z = 0.4 # spin slowly to search else: ys, xs = np.where(red_mask) # pixel coordinates of all red pixels cx = float(np.mean(xs)) # horizontal centroid of the red blob offset = (cx - w/2) / (w/2) # normalised offset: −1 = far left, +1 = far right twist.angular.z = -0.8 * offset # steer toward target (negative because axes flip) twist.linear.x = 0.3 # drive forward (m/s)

Demo B — UR5 wrist camera detector

The UR5 arm has a camera at its end-effector (tool flange). As you move the arm, the camera's view changes. This is the eye-in-hand configuration used in robotic pick-and-place.

1
Launch UR5 with wrist camera. 
$ ros2 launch ur5_camera_description ur5_camera.launch.py
[launch] Published /robot_description
[sim] UR5 Arm — wrist camera at wrist_3_link
[sim] Publishing /wrist_camera/image_raw at 10 Hz
2
Optionally animate the arm. Run ros2 run ur5_control joint_sine_demo to make the arm sweep — you'll see the camera view change as wrist_3 rotates.
3
Add coloured obstacles and run the detector: 
$ ros2 run ur5_vision wrist_detector
[INFO] [wrist_detector]: Detected — red: pos=(0.48,0.52) area=4.1%  |  blue: pos=(0.72,0.61) area=2.3%
Position values are normalised (0,0) = top-left, (1,1) = bottom-right of the camera frame.
⚠️

Camera orientation. The wrist camera is attached in the arm's joint frame. The exact view direction depends on the current wrist_3 angle. Rotate the arm to aim the camera at objects in the scene.

Image message API reference

Camera topics publish sensor_msgs/Image messages. In Python, you receive them in a subscription callback:

Python — import pattern
from sensor_msgs.msg import Image # camera message type import numpy as np # NumPy for pixel math def callback(msg): # called for each camera frame arr = np.asarray(msg.data, dtype=np.uint8).reshape(msg.height, msg.width, 3) # arr is now a (H, W, 3) uint8 NumPy array — standard RGB, ready for pixel math

The fields of sensor_msgs/Image:

FieldTypeValue in ROSpad
header.frame_idstrLink name (e.g. "camera_link")
heightint240 (default)
widthint320 (default)
encodingstr"rgb8"
stepintwidth × 3 bytes per row
dataJsProxy (Uint8Array)Raw RGB bytes — use np.asarray(msg.data, dtype=np.uint8)
ℹ️

msg.data is a JavaScript Uint8Array passed directly from the renderer. NumPy can consume it via np.asarray() without copying. Do not try to iterate it as a Python list — it will be slow.

6

Writing your own vision node

Use image_info.py as a starting template — it's the minimal subscriber with NumPy access:

Python — minimal vision node template
import numpy as np # NumPy for pixel math import rclpy # ROS 2 Python library from rclpy.node import Node # base class for every node from sensor_msgs.msg import Image # camera frame message from geometry_msgs.msg import Twist # velocity command message class MyVisionNode(Node): def __init__(self): super().__init__('my_vision_node') # register node name self.create_subscription(Image, '/camera/image_raw', self.on_image, 10) # subscribe to camera self._pub = self.create_publisher(Twist, '/cmd_vel', 10) # publisher for drive commands def on_image(self, msg): # called for every camera frame # 1. Convert to NumPy array img = np.asarray(msg.data, dtype=np.uint8).reshape(msg.height, msg.width, 3) # 2. Process: detect, threshold, find blobs, etc. brightness = float(np.mean(img)) # average pixel brightness 0–255 self.get_logger().info(f'Mean brightness: {brightness:.1f}') # 3. Act: publish velocity, log results, etc. def main(): rclpy.init() # start the ROS 2 runtime rclpy.spin(MyVisionNode()) # create node and loop until Ctrl-C if __name__ == '__main__': main()
🎨

Colour detection

Threshold by RGB channel: mask = (img[:,:,0] > 150) & (img[:,:,2] < 80) gives red pixels.

📍

Centroid finding

ys, xs = np.where(mask) then cx = np.mean(xs) gives the horizontal centre of the detected region.

📏

Area estimation

area = np.sum(mask) / (w*h) estimates how much of the image is covered — useful as a proxy for distance.

🔍

Edge detection

Use np.gradient(img[:,:,0].astype(float)) for a simple Sobel-like gradient without OpenCV.

Troubleshooting

?
/camera/image_raw doesn't appear in the Topics panel.
Make sure you launched diffbot_camera_description, not the plain diffbot_description. The plain description has no camera sensor in its URDF.
?
Topics panel shows the topic but the canvas preview is black.
The camera rendered before the robot loaded. Stop the sim (■ Stop), re-launch, and click the topic again. This is a one-time startup race.
?
ValueError: cannot reshape array of size 0 into shape (240, 320, 3)
The subscription fired before the first image arrived. Add a guard: if not msg.data or msg.width == 0: return at the top of your callback.
?
Robot doesn't move after running color_tracker.
Confirm the robot is a DiffBot (not UR5). Only DiffBot responds to /cmd_vel from the sim bridge. Also check that the sim is running (not paused).
?
New packages not in file tree.
Click ⊘ in the sidebar to re-seed. This adds any new packages that are in the index but not yet in your repo.
🔬

Quick pipeline check: Run ros2 run ur5_vision image_info right after launching the camera URDF. It prints the image dimensions and mean RGB every 10 frames. If you see output, the camera pipeline is working end-to-end.
